# 管理员定向通知与已有订阅额度调整

## 定向通知

`POST /api/admin/notifications`，需要 `users.write`，支持 `?dryRun=true`。

```json
{
  "target": { "userIds": ["用户 UUID"], "groupIds": ["用户组 UUID"] },
  "title": "感谢大家的支持！",
  "body": "福利余额已经到账，祝大家使用愉快！",
  "link": "/console/billing",
  "severity": "info",
  "idempotencyKey": "本次发送的 UUID"
}
```

- 单个用户、用户列表、多个用户组可以同时选择，取并集后去重；仅发送给启用用户。空范围不代表全部用户，未知用户或用户组返回 404。
- 标题 1–200 字，正文 1–10000 字；级别为 `info`、`warning`、`critical`，默认 `info`。链接可省略，只允许站内绝对路径。
- 响应 `{ "recipients": 12, "alreadySent": false }`。预览只验证并统计，不写入通知、投递队列或审计。
- 同一发送者的 `idempotencyKey` 在重试时保持不变。同标识、同内容的重试不会重复发送或重复审计；换内容需换标识。
- 事件类型 `admin.message`，站内通知始终开启；邮件和 Webhook 默认关闭，仅在接收人主动启用对应偏好时投递。
- 发送及审计 `notification.send` 在同一事务提交。每次最多指定 1000 个用户和 1000 个用户组，解析后接收人数最多 10000。

控制台入口：用户列表的「发送通知」（可使用勾选列表和当前分组），或用户详情里的「发送通知」。

## 修改已有订阅的容量和余量

`POST /api/admin/billing/subscriptions/adjust-quota`，需要 `billing.manage`，支持 `?dryRun=true`。

```json
{
  "target": { "ids": ["订阅 UUID"] },
  "ruleId": "weekly",
  "limit": "100",
  "remaining": "80",
  "note": "补偿并调整容量"
}
```

- `target` 同批量重置：`{ids}`，或 `{status:"active",planIds:[],groupIds:[]}`；仅处理有效且未到期、包含该规则 ID 的订阅。可包括已下架套餐的存量订阅。
- `limit`、`remaining` 至少提供一项；省略的上限或已用量保持原值。只改容量时，余量按新容量减原已用量计算。填写余量则将当前窗口用量调整为「新上限减余量」，后续窗口仍使用规则上限。
- 上限大于 0，余量在 0 与上限之间。请求次数、Token、图片等计量使用整数；金额与自定义计量最多 9 位小数。
- 直接调整窗口计数并写入审计，不修改实际请求日志或钱包账单；审计记录前后上限、用量和原刷新时间。
- 保留 `windowStart`、`resetsAt`、订阅到期时间。未开始的会话或无活动桶的滚动窗口不允许凭空加入已用量：先修改上限，首次使用后再调整余量。
- 滚动窗口减用量时先减最新桶，加用量时计入最早的活动桶；桶时间不移动。
- 响应沿用批量操作 `{affected, subscriptions}`。整批在一个事务中提交，任何一项校验失败都会回滚；预览不写入数据。

控制台入口：订阅管理的「调整额度」，支持单份、勾选列表、套餐和用户组筛选。

## 将套餐额度同步给已有订阅

`PATCH /api/admin/billing/plans/{id}` 新增可选 `syncSubscriptionLimits: true`。

按规则 ID 同步该套餐现有有效订阅的上限，只同步计量、窗口、计量模型、模型权重和自定义计量版本兼容的规则。仅修改容量，保留已用量、刷新时间、到期时间及模型列表；不增加或删除订阅原有规则。遇到同 ID 不兼容规则时整个套餐保存回滚，返回 422。原有 `syncSubscriptionModels` 独立控制模型同步，两项均默认关闭。

控制台「编辑套餐」中可开启「同步已有订阅的额度上限」，已下架套餐同样支持。调整某个用户的余量使用上面的订阅调整接口。

## 重置时间

管理员重置和用户重置卡使用同一路径：只把当前窗口的用量清零，保留已有计数行和窗口时间；未开始的会话不会被重置操作启动。日历、周期和总量窗口的时间边界也保持不变。

### 补充老订阅缺失的规则

`PATCH /api/admin/billing/plans/{id}` 可传 `syncSubscriptionRules: true`，默认关闭。
按规则 ID 将套餐中缺失的规则追加到有效订阅；同 ID 规则不覆盖，不删除老规则，不清零用量，不修改起止时间或刷新时间。新规则只统计同步后结算的请求，不追溯历史；重复同步保留新增规则已累计的用量。合并超过规则数量上限时整个保存回滚。
可同时开启 `syncSubscriptionModels`，原子同步模型与新增限制；额度上限、模型倍率仍由各自开关控制。审计记录 `syncedSubscriptionRules`。编辑套餐即使模型列表没有再次变化，也可同步当前模型列表。
