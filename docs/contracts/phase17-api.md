# 契约：Round 17 —— 套餐分组（组内升级）

> 状态：**已实现**。通用约定同前；所有 SQL 同时支持 PostgreSQL 与 SQLite（迁移 `00022_plan_groups`）。
> 需求：国模套餐与 GPT 套餐不能互相升级；同一组内可以平滑补差价升级。

## 1. 字段

套餐新增 `group`（字符串，最多 50 个字符，前后空白去除；默认 `""` = 未分组）。

- 管理端 `GET / POST / PATCH /api/admin/billing/plans`：读写 `group`（PATCH 省略 = 不变）。
- 用户端 `GET /api/plans` 与 `GET /api/billing/purchase/options` 的 `plan` 条目带 `group`。

## 2. 升级规则

补差价升级（phase15-api.md §2）只在**同一分组**的套餐之间进行：来源订阅的套餐与目标套餐的 `group` 必须相同
（未分组的套餐自成一组）。不同分组时购买选项中不出现该升级，直接请求返回 `409 not_an_upgrade`（“不同分组的套餐不能互相升级”）。
来源套餐取订阅当前引用的套餐（已下架的旧套餐同样按其 `group` 判断，可把旧套餐也设为同一分组以允许其订阅升级到新套餐）。

购买与续费不受分组影响。

## 3. 购买页

用户可见的套餐按售价从低到高排列；购买页按分组分段展示（只有一个分组时不显示分组标题），分组顺序为该组第一个套餐出现的位置。
