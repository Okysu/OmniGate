# 威胁模型（Round 3 更新）

> 方法：按资产 → 信任边界 → STRIDE 威胁 → 缓解措施梳理。✅ 表示本轮已实现并有测试覆盖；⏳ 表示设计已定、在后续阶段实现。

## 1. 资产

| 资产 | 敏感度 | 说明 |
| --- | --- | --- |
| 上游 API Key / 渠道凭据 | 极高 | 泄露意味着直接的经济损失 |
| 主密钥 `OMNIGATE_MASTER_KEY` | 极高 | 可以解密全部渠道凭据 |
| Gateway Key | 高 | 可以消耗额度与余额 |
| 钱包余额、兑换码 | 高 | 等价于钱 |
| 会话 Cookie | 高 | 等价于控制台登录 |
| 请求内容（Prompt/响应） | 高 | 默认不落盘 |
| 用量与账单数据 | 中 | 影响计费正确性 |
| 审计日志 | 中 | 需要防篡改、防删除 |

## 2. 信任边界

1. 互联网 ↔ 反向代理/omnigate（客户端 SDK、浏览器）
2. omnigate ↔ IdP（GitHub / OIDC）
3. omnigate ↔ 上游厂商 API
4. 宿主 Go 代码 ↔ 插件 JS 沙盒（**最重要的内部边界**）
5. omnigate ↔ PostgreSQL / Redis
6. 普通用户 ↔ 管理员（同一控制台内的权限边界）

## 3. 威胁与缓解

### 认证与会话

| 威胁 | 缓解 | 状态 |
| --- | --- | --- |
| OAuth CSRF / 登录劫持 | 加密 state Cookie（单次使用、10 分钟）、state 比对、PKCE S256、OIDC nonce | ✅ 测试：state 伪造被拒 |
| 开放重定向 | `SafeRedirect` 只允许同站路径，拒绝 `//`、`/\`、换行、`/api/` | ✅ 单元 + 集成测试 |
| 会话令牌被盗用 | 256 bit 随机令牌；数据库只存 SHA-256；HttpOnly、生产环境 Secure、SameSite=Lax；空闲超时与绝对超时；可撤销 | ✅ |
| 控制台 CSRF | 非 GET 请求必须带 `X-Requested-With`，并校验 Origin；CORS 关闭 | ✅ 测试：缺头/外来 Origin 被拒 |
| 账号接管（通过邮箱合并） | 不按邮箱自动合并账号；身份键为（provider, 不可变 subject） | ✅ |
| GitHub login 被改名后抢注 | 推荐使用 `github-id:` 匹配；引导管理员规则只在首次创建账号时生效 | ✅（文档提示） |
| 暴力尝试登录/回调 | 按 IP 前缀限流 | ✅（进程内；多实例时改用 Redis ⏳） |
| 被停用用户继续访问 | 每个请求都检查用户状态 | ✅ 测试 |
| 最后一位管理员被误降级/误停用 | 事务内检查，返回 `last_admin` | ✅ 测试 |

### 越权

| 威胁 | 缓解 | 状态 |
| --- | --- | --- |
| 普通用户调用管理 API | 每个路由声明权限，服务端强制校验 | ✅ 测试：403 |
| 修改资源 ID 访问他人资源（IDOR） | 资源查询带所有者/作用域条件；会话、Key 只能操作自己的；他人私有渠道返回 404 | ✅ 集成测试 |
| 共享渠道使用者读取密钥 | `shared`/`global` 只授予“使用”，仅返回精简视图；密钥只返回末 4 位 | ✅ 集成测试 |
| 并发修改互相覆盖 | 乐观锁 `version` | ✅ 测试：409 |

### 凭据与数据

| 威胁 | 缓解 | 状态 |
| --- | --- | --- |
| 数据库泄露导致凭据泄露 | AES-256-GCM 加密存储，主密钥不在数据库中；AAD 绑定行与字段 | ✅ 渠道凭据已接入 |
| 日志泄露密钥 | 访问日志不记录头部、查询串、请求体；上游错误信息经脱敏；集成测试与真实上游实测扫描日志/审计/响应均无明文 | ✅ |
| 完整客户端 IP 被留存 | 只存 /24（IPv4）或 /48（IPv6）前缀 | ✅ |
| 兑换码被枚举 | 100 bit 熵、只存 SHA-256 摘要、每用户限流、码不存在时统一返回 `redeem_invalid` | ✅（按 IP 限流未做） |
| 重复扣费 / 漏记 | 以 request_id 为幂等键（部分唯一索引）；失败请求不收费；并发结算测试 | ✅ |

### 数据面（Round 2 新增）

| 威胁 | 缓解 | 状态 |
| --- | --- | --- |
| 普通用户通过渠道 baseUrl 做 SSRF（云元数据、内网） | 创建时拒绝内网字面地址；拨号时校验解析后的 IP；不跟随重定向；忽略代理环境变量；仅管理员 + 显式开关可连内网 | ✅ 单元 + 集成测试 |
| 上游错误信息回显上游 Key | 401/403 不透传正文；其他错误信息经正则脱敏、截断 | ✅ 集成测试 |
| 停用用户 / 吊销 Key 后仍可调用 | 认证缓存 10s，停用用户与 Key 变更时立即清空 | ✅ 集成测试 |
| 客户端伪造 Header 透传上游 | 只透传 `anthropic-version`、`anthropic-beta`；自定义头禁止鉴权与逐跳头 | ✅ |
| 超大请求 / 响应耗尽内存 | 请求体 32 MiB；非流式响应 64 MiB；SSE 单事件 16 MiB；流式空闲 5 分钟断开 | ✅ |

### 插件沙盒（ADR-0002）

| 威胁 | 缓解 | 状态 |
| --- | --- | --- |
| SSRF（访问内网、云元数据） | `og.fetch` 只允许 manifest 声明的主机，复用渠道的防 SSRF 客户端（拨号时校验 IP），不跟随重定向，默认只允许 https | ✅ 引擎测试 |
| 死循环 / CPU 耗尽 | 墙钟超时 → `Interrupt`；按插件版本限制并发；被中断的运行时丢弃不复用 | ✅ 引擎测试 |
| 内存耗尽 | 输出上限、fetch 响应上限、看门狗按进程堆增长中断、5 分钟 3 次违规自动停用插件（**无单插件硬上限**，已知残余风险） | ✅ 引擎 + 集成测试 |
| 读取明文密钥 | 只给带随机 nonce 的句柄，仅在 `og.fetch` 与 Hook 返回的请求头中替换；HMAC 在 Go 侧完成；日志与错误中的句柄/明文被脱敏 | ✅ 引擎测试 |
| 恶意插件代码来源 | 只有 `plugins.manage` 可以创建/导入/发布；首个版本与权限变化的版本必须由 `plugins.trust` 审批后才能被渠道使用；编译期禁止导入外部模块；静态扫描仅作提示（订阅源在 Round 4） | ✅ 集成测试 |
| 插件 UI 的 XSS / 钓鱼 | 只允许白名单声明式组件，manifest 校验拒绝其他组件；外链仅 https；markdown 以纯文本渲染 | ✅ |

### 插件请求 Hook（Round 3 新增）

| 威胁 | 缓解 | 状态 |
| --- | --- | --- |
| Hook 把请求改发到其他主机，窃取上游 Key | Hook 只能改 `path`（必须以 / 开头、不含主机），主机固定为渠道 Base URL | ✅ |
| Hook 拖慢或阻断数据面 | 每个 Hook 50ms 超时；失败按可回退错误处理并计入熔断；未声明 Hook 的插件在热路径上零 JS 调用 | ✅ 集成测试 |
| 共享渠道使用者看到所有者的余额等账户信息 | 能力接口与结果只对渠道所有者和 `channels.manage` 开放 | ✅ |

## 4. 残余风险（需要知晓）

1. Goja 无单插件内存硬上限（ADR-0002），依靠看门狗与“只有管理员能安装插件”来缓解。
2. 开发模式下第一个登录的人会成为管理员；**切勿把开发模式暴露到公网**（生产模式会拒绝这种配置）。
3. 主密钥丢失将导致凭据无法恢复；主密钥泄露需要立即轮换，并在上游吊销所有凭据。
